# setup-server.sh

Интерактивный скрипт базовой настройки чистого VPS на Ubuntu или Debian. Выполняет пошаговую настройку безопасности, Docker, swap, фаервола и защиты от брутфорса.

## Требования

- **ОС:** Ubuntu 20.04 / 22.04 / 24.04 / 26.04 (только LTS) или Debian 12 / 13 (Debian 11 не поддерживается — её LTS закончилась 31.08.2026; на другой ОС скрипт предупредит и запросит подтверждение)
- **Доступ:** root (через `sudo`)
- **Интернет:** для установки пакетов и Docker

## Быстрый старт

### Запуск напрямую из GitHub (рекомендуется)

```bash
bash <(curl -s https://raw.githubusercontent.com/CosmoFox/cook-server/main/setup-server.sh)
```

Или через `wget`:

```bash
bash <(wget -qO- https://raw.githubusercontent.com/CosmoFox/cook-server/main/setup-server.sh)
```

### Локальный запуск

#### 1. Скопируйте файлы на сервер

```bash
# Со своего локального компьютера:
scp setup-server.sh root@<IP-сервера>:/<Путь>/
```

Или клонируйте репозиторий:

```bash
git clone https://github.com/CosmoFox/cook-server.git /opt/cook-server
cd /opt/cook-server
```

#### 2. Сделайте скрипт исполняемым

```bash
chmod +x setup-server.sh
```

#### 3. Запустите

```bash
./setup-server.sh
```

## Запуск без меню (автоматизация)

Скрипт поддерживает неинтерактивный режим — меню не показывается:

| Флаг | Действие |
|---|---|
| `--all` | Выполнить все шаги без меню |
| `--steps=1,3,5` | Выполнить указанные шаги без меню |
| `--yes`, `-y` | Не запрашивать подтверждение перед запуском и не перезагружать сервер в конце |
| `--help`, `-h` | Показать справку |

```bash
# Полностью неинтерактивный прогон:
./setup-server.sh --all --yes

# Только базовые пакеты и настройка SSH:
./setup-server.sh --steps=2,6 --yes
```

⚠ В неинтерактивном режиме файл `.token` должен существовать заранее — скрипт никогда не подтверждает за пользователя загрузку закрытого ключа. Сгенерируйте ключи один раз в интерактивном режиме.

Если какой-то шаг завершится с ошибкой, прогон не прерывается: ошибка фиксируется, выполняются остальные шаги, в конце выводится сводка. Код выхода скрипта — `1`, если хотя бы один шаг упал.

## Файлы

| Файл | Назначение |
|---|---|
| `setup-server.sh` | Основной скрипт настройки |
| `.token` | Содержит SSH-публичный ключ для авторизации. Если файла нет — скрипт предложит сгенерировать пару ключей |
| `id_ed25519_*` / `id_rsa_*` | Закрытый SSH-ключ (создаётся при генерации). Имя зависит от выбора: hostname, IP или вручную. **Скачайте и удалите с сервера!** |
| `setup-server-*.log` | Лог прогона (создаётся рядом со скриптом автоматически) |

## Доступные шаги

### 1. Обновление системы

- `apt update` → `apt upgrade` → `apt autoremove`
- Обновляет репозитории, устанавливает последние версии пакетов, удаляет ненужные
- apt работает в неинтерактивном режиме (никаких диалогов посреди прогона)

### 2. Установка базовых пакетов

| Пакет | Зачем |
|---|---|
| `curl` | HTTP-запросы из командной строки |
| `htop` | Интерактивный мониторинг процессов |
| `mcedit` (`mc` на Debian) | Простой текстовый редактор |
| `fail2ban` | Защита от брутфорса (настраивается в шаге 7) |
| `openssh-server` | SSH-сервер |
| `openssh-client` | Нужен для `ssh-keygen` при генерации ключей |

### 3. Установка Docker

- Подключает официальный репозиторий Docker (адрес выбирается автоматически: `/linux/ubuntu` или `/linux/debian`)
- Устанавливает: `docker-ce`, `docker-compose-plugin`, `docker-buildx-plugin`
- Включает и запускает сервис `docker`
- Пропускает установку, если Docker уже есть

### 4. Настройка swap (2 ГБ)

- Создаёт `/swapfile` на 2048 МБ
- Права `600`, форматирует, активирует
- Добавляет запись в `/etc/fstab` для автоподключения
- Устанавливает `vm.swappiness=10` (`/etc/sysctl.d/99-swap.conf`) — без агрессивного свопирования
- Пропускает создание файла, если swap уже активен

### 5. Настройка UFW (фаервол)

- Сбрасывает существующие правила
- Default: **deny incoming**, **allow outgoing**
- Открывает порты:

| Порт | Протокол | Назначение |
|---|---|---|
| 2288 | TCP | SSH |
| 80 | TCP | HTTP |
| 443 | TCP | HTTPS |

- Включает UFW

**Защита от ошибки порядка:** перед включением скрипт проверяет, что sshd действительно слушает порт 2288. Если SSH ещё не перенесён на 2288 и шаг 6 не выбран — UFW не включается, доступ к серверу сохраняется.

### 6. Настройка SSH

⚠ ВНИМАНИЕ: Этот шаг полностью перезаписывает файл `/etc/ssh/sshd_config`. Все текущие пользовательские настройки SSH будут удалены и заменены стандартными значениями скрипта.

Полная перезапись `/etc/ssh/sshd_config`:

| Параметр | Значение |
|---|---|
| `Port` | 2288 |
| `PermitRootLogin` | prohibit-password (root по ключу, без пароля) |
| `PasswordAuthentication` | **no** |
| `PubkeyAuthentication` | yes |
| `MaxAuthTries` | 3 |
| `LogLevel` | VERBOSE — иначе sshd не пишет неудачные входы по ключу, и fail2ban слеп к ним |
| `X11Forwarding` | no |

- **Валидация перед отключением пароля:** если содержимое `.token` не похоже на SSH-публичный ключ, шаг прерывается — парольная аутентификация остаётся включённой, доступ не теряется
- Устанавливает публичный ключ из `.token` в `/root/.ssh/authorized_keys` — ключ **дописывается**, ранее добавленные вручную ключи не затираются
- Проверяет конфигурацию через `sshd -t` до перезапуска сервиса
- Рестартует SSH-сервер

### 7. Настройка fail2ban

- Банит на **24 часа** после **3 неудачных попыток** за **10 минут**; неудачные входы **по ключу тоже считаются** (`filter = sshd[publickey=any]`) — без этого при отключённом парольном входе бан не срабатывал бы вовсе, так как sshd по умолчанию фиксирует только неудачные пароли
- Источник логов выбирается автоматически: если есть `/var/log/auth.log` (rsyslog) — чтение файла, иначе journald с учётом особенности Debian/Ubuntu (юнит `ssh.service`)
- Дополнительно включён jail `[recidive]` — рецидивисты банятся на неделю
- Включает сервис

### 8. Автообновления безопасности

- Устанавливает `unattended-upgrades`
- Ежедневно обновляет списки пакетов и ставит **только обновления безопасности** (включая ESM)
- Раз в неделю чистит кэш apt, удаляет ставшие ненужными зависимости
- Автоматической перезагрузки не включает

## Генерация SSH-ключей

Если файл `.token` отсутствует при запуске, скрипт предложит сгенерировать пару ключей:

1. **Выберите тип ключа:**
   - `1` — **ED25519** (рекомендуется, быстрее, компактнее)
   - `2` — **RSA 4096-bit** (для совместимости со старыми системами)

2. **Выберите имя файла ключа:**
   - `1` — по **hostname** сервера: `id_ed25519_web-1`
   - `2` — по **IP-адресу**: `id_ed25519_10.0.0.5`
   - `3` — **hostname + IP**: `id_ed25519_web-1_10.0.0.5`
   - `4` — **ввести вручную** (дополнительная метка)

3. Ключи генерируются без passphrase:
   - Открытый ключ → `.token`
   - Закрытый ключ → файл с выбранным именем (рядом со скриптом)

4. **⚠ Скрипт покажет предупреждение** — обязательно скачайте закрытый ключ до продолжения, иначе потеряете доступ к серверу!

5. **Опционально: генерация .ppk для PuTTY** — после создания ключа скрипт спросит, нужен ли формат PuTTY:
   - `y` — конвертирует ключ в `.ppk` через `puttygen` (установка: `apt install -y putty-tools`)
   - `N` / Enter — пропустить

### Подключение с новым ключом

```bash
ssh -i /путь/к/id_ed25519_web-1 -p 2288 root@<IP-сервера>
```

## Порядок выполнения

Рекомендуется запускать шаги в таком порядке:

1. Обновление системы
2. Установка базовых пакетов
3. Установка Docker
4. Настройка swap
5. Настройка UFW
6. Настройка SSH ← **после этого парольный доступ отключается!**
7. Настройка fail2ban
8. Автообновления безопасности (можно в любой момент)

Для полной настройки — нажмите `A` (выбрать все) → `Enter`.

## После перезагрузки

Проверьте:

```bash
# SSH подключается только по ключу на порту 2288:
ssh -i ~/.ssh/id_ed25519 -p 2288 root@<IP>

# Фаервол активен:
ufw status verbose

# Docker работает:
docker run hello-world

# fail2ban активен:
fail2ban-client status
```

## Примечания

- Скрипт идемпотентен — повторный запуск безопасен (Docker, swap, UFW пропускаются, если уже настроены, ключ в `authorized_keys` не дублируется)
- Если `.token` пустой или отсутствует (и вы отказались генерировать ключи) — скрипт не продолжит работу
- Порт SSH изменён со стандартного 22 на 2288
- Парольная аутентификация SSH отключена
- Весь прогон пишется в лог `setup-server-<дата>.log` рядом со скриптом — при сбое начинайте разбор с него
- Если шаг падает с ошибкой, прогон продолжается; сводка по упавшим шагам выводится в конце
